01 / SCRIPTING ARCHITECTURE

Gameplay code.
Its own project.

I introduced a separate C++ gameplay project compiled as a DLL, with script instances attached to scene objects.

A ScriptComponent owns the instance and calls its lifecycle methods. Registration makes script types available by name, while the exported EngineAPI gives gameplay code access to engine services through an import library.

This let the team develop character and enemy behavior outside the engine project, while retaining access to transforms, input and scene objects.

02 / INSPECTOR INTEGRATION

Configure behavior
where it is used.

I connected C++ script members to Inspector controls and scene serialization.

The field system supports inherited settings, component references and reference lists, plus labels and collapsible groups for larger configurations. Dedicated field handlers keep operations such as drawing, saving, cloning and reference resolution extensible.

Reference lists and field refactor · PR #107 ↗

03 / SCRIPT HOT RELOADING

Rebuild. Restore.
Keep working.

I added an editor action to build and reload scripts without restarting the engine.

Compilation runs asynchronously while an editor modal communicates progress. If compilation fails, the current scripts stay loaded. After a successful build, the main thread saves exposed fields, destroys the old instances, replaces the DLL, recreates scripts and restores their values and scene references.

The reload action is performed outside Play mode. Runtime DLL and PDB copies are versioned to avoid conflicts with files held by the process.

04 / SCENE INTERACTION

Connect the scene
to the workflow.

Triggers with a runtime lifecycle

I implemented editable trigger volumes, overlap tracking and OnTriggerEnter / OnTriggerExit callbacks. Scene-owned trigger state handles registration and cleanup as scenes load and objects spawn or are destroyed.

Pick the object you can see

I implemented viewport ray construction and two-stage picking: bounding boxes identify candidate renderers, then triangle intersections find the closest visible surface. Selection reveals the object in the hierarchy and only responds to clicks inside the Scene viewport.
